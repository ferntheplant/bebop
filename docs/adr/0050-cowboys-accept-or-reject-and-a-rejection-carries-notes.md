# Cowboys accept or reject, and a rejection carries notes

Jet and faye do the same job: probe one candidate and return a verdict. The verdict is binary — **accept** or **reject** — and it is the only part of their output the workflow acts on. Per-item severity is gone. Grading each item asked a cowboy to spend judgement on a distinction nothing consumed, and turned "how bad is this" into an argument the system then discarded. Cowboys are instructed to explain themselves in whatever detail the case deserves; what is stored and acted on is one bit, plus prose.

A rejection must carry **notes**: a list of things to address. A note is a markdown body, optionally anchored to a file and line, and optionally referencing evidence artifacts — so it can point at the line that is wrong, or at the screenshot showing it. Notes carry no severity, no title, and no identity. Nothing carries a note across candidates and nothing closes one like a checklist, so its position within a verdict is identity enough. An acceptance may carry notes too — the observations a reviewer had that were not worth rejecting over — and those are kept and surfaced with the accepted candidate rather than dropped.

A rejection with **no** notes is not a verdict. It sends ein back to work with nothing to act on, and it is undiagnosable afterwards. It consumes one of that gate's attempts and re-prompts **the same seat** for actionable notes. The seat that formed the judgement is the only one that can say why it rejected; a fresh seat would have to redo the entire review to write down a conclusion it never reached, and might return the opposite verdict — leaving an operator to interpret "the reviewer rejected this and its replacement accepted it". A fresh seat is for an attempt that collapsed, not for a result that arrived malformed. An acceptance with no notes stays valid: silence only fails when work is being sent back.

The two cowboys reach a verdict differently, and the asymmetry is deliberate. **Jet declares** its verdict, having no smaller unit of work to compute one from. **Faye's is derived**: any failed scenario rejects the candidate, and nothing else does. The scenario is faye's unit of work, so a computed verdict stays auditable against faye's own table instead of asserted beside it. When faye meets an edge case no listed scenario covers, it writes that scenario and fails it — which makes the observation reproducible rather than a claim.

Notes are kept per candidate, permanently. A candidate that jet accepted with notes and faye then rejected leaves both records readable long after the next candidate exists. What ein _receives_ is only the current candidate's notes: a feedback packet is bound to one candidate SHA, and replaying notes about code that no longer exists is exactly the failure [Every commit invalidates every downstream result (ADR 0016)](./0016-every-commit-invalidates-every-downstream-result.md) refuses partial invalidation to avoid.

## Consequences

**Accept** and **reject** are reserved for cowboy decisions. A validator or a CI check _fails_; it does not reject, because it exercised no judgement. Collapsing the two would lose the distinction an operator most needs — whether anybody actually thought about this candidate. `GateOutcome` stays `passed` / `failed` as the mechanical value the workflow branches on: the verdict is what a cowboy produced, the gate outcome is what the workflow recorded.

Jet and faye share one verdict shape, with faye's scenarios as an additional QA-only payload. Two gates whose outputs were structurally unrelated become one thing with one renderer, one evidence layout, and one feedback-packet entry — and the claim that they do the same job becomes checkable by a type rather than asserted in prose.

The shipped contract does not match this yet. `ReviewFinding` still carries a severity, Swordfish still stores a `findings` table, and the evidence kind is still `review_findings`. Nothing derives a gate outcome from findings, so no behaviour is wrong today — only the vocabulary is, and it is tracked as build work rather than left to drift into the first code that consumes it.

Instructing richly while storing one bit means the instruction is now load-bearing and unversioned. A cowboy told to reject only for defects that matter, and one told to reject on any deviation, produce the same schema and a different system. That prompt is where this decision actually lives at runtime.
