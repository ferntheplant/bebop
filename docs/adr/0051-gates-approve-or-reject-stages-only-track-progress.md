# Gates approve or reject; stages only track progress

A **gate** is a point where a candidate can be stopped. There are four, and they are the whole pipeline a candidate must survive: local validation, external CI, jet's review, and faye's QA. A **stage** is a position in the state machine Swordfish and bebop use to track what is happening — `implementing`, `qa_preparing`, `needs_attention`, `cancelling`. The two were being spelled with one word: `verificationStages` named gates, [Readiness is a claim (ADR 0003)](./0003-readiness-is-a-claim-not-authority.md) said "Swordfish's required stages passed for it" meaning gates, and `CONTEXT.md` defined stage as a workflow position. A term that names both a checkpoint and a location cannot be used precisely in either sense.

Every gate **approves** or **rejects**. Previously the two deterministic gates passed or failed while the two cowboys accepted or rejected, which meant a reader had to know which gate produced an outcome before knowing which verb described it. The distinction was never real: a validator suite exiting non-zero and jet writing a rejection are the same event — this candidate may not proceed. `passed` / `failed` described the mechanism, and the mechanism is exactly the part that differs between a shell exit code and a model's judgement. What every gate has in common is the consequence, so the consequence is what the vocabulary names. **Accept** is retired in favour of **approve**, so one pair of words covers all four gates rather than two pairs split along a line nothing downstream cares about.

`evidence_upload` is therefore not a gate. It judges nothing, its only legal feedback is `unstructured`, and it cannot stop a candidate on merit — it can only break. It stays a stage, and something other than a gate outcome must record that evidence landed before a bounty reaches `ready`.

**Failed** is reserved for a gate that rejected, so terminal states that mean "something broke" are **errored** instead. A bounty and a Swordfish stage each had a `failed` value meaning an unexpected system condition, which read as though a candidate had been judged. The endings are now `done` (merged), `stopped` (deliberately halted), and `errored` (something unexpected) — three genuinely different ways to stop rather than two and a synonym.

**Agent** is retired everywhere in favour of **cowboy**. `CONTEXT.md` has said to avoid it since it collides with OpenCode's own vocabulary and wrongly includes deterministic Swordfish, but the contract still carries `agentDispositions`, `agent_blocked`, and two `UnstructuredFeedbackReason` members. A glossary that the schema contradicts is a glossary nobody can rely on.

## Consequences

The contract renames follow: `verificationStages` collapses into `candidateGates` — now the same four members, so keeping two lists invites drift; `gateStatuses` becomes `not_started | pending | approved | rejected` with `GateOutcome` derived from it rather than declared twice; `agentDispositions` becomes `cowboyDispositions`; and `stage_aborted_before_output` and `stage_infrastructure_failure` become `gate_`-prefixed, since the thing that aborted was a gate.

`rerunTargets` is deliberately left alone. It looked like a fifth spelling of the four gates and is not: it is `constraintScopes` (`building`, `review`, `qa`, one per cowboy) plus `validation`, which repeats a deterministic gate on the same SHA and consumes no attempt. A rerun grants an attempt in a scope; it does not name a gate. `building` has no gate at all, because ein is not a checkpoint.

Approval now spans two altitudes with two words that must not merge: a **gate** approves a candidate, and a human **approves config** under a privileged path ([`.bebop/**` is permanently privileged (ADR 0011)](./0011-the-bebop-directory-is-permanently-privileged.md)). They are different acts by different actors over different objects, and `approve_config` keeps its own name precisely so that a gate approval can never be mistaken for authority a human granted.

This is vocabulary, not behaviour. No state transition, permission, or outcome changes meaning; the same events are recorded and the same decisions are made. It is worth an ADR anyway, because the previous names were actively teaching a wrong model — that deterministic gates and cowboy gates do different kinds of thing, and that a stage and a checkpoint are the same kind of thing.
