# QA

Someone actually uses the thing before you are asked to merge it. Faye drives a browser against a running
instance of the candidate, in an environment built from scratch for that exact commit, and checks the acceptance
criteria the effective spec declared.

## What you can expect

- **QA runs last, and only on a candidate that earned it.** It begins only after both external CI and code review
  have passed for the exact candidate SHA — there is no point driving a browser against code a reviewer is about
  to reject.
- **A clean environment, not a reused one.** Swordfish prepares QA through your repository's hooks in a fresh
  worktree with disposable runtime state, so a passing scenario is not passing on data an earlier run left
  behind.
- **Real browser evidence**: screenshots, recordings, console logs, network logs, and structured scenario
  outcomes.
- **Faye never edits code.** It has repository read access, browser automation, and private preview access. A QA
  cowboy that can fix what it finds is not a QA cowboy.
- **A fresh seat for every attempt.** A rerun or revised candidate cannot inherit faye's prior context.
- **Two completion attempts by default.** If faye's attempt collapses — no output, or output that does not decode
  — Swordfish may start one automatic fresh-seat attempt. A rejection completes the gate and starts a new ein
  build cycle; it is never retried autonomously.
- **Faye's verdict is computed, not asserted.** Any failed scenario rejects the candidate, and nothing else does,
  so the verdict is always auditable against faye's own scenario table. A rejection carries notes for ein, the
  same as jet's.
- **An uncovered edge case becomes a scenario.** When faye finds a problem no listed scenario describes, it
  writes that scenario and fails it — which makes the observation reproducible instead of a claim in prose.
- **Checked against your acceptance criteria**, which is why the effective spec must declare at least one.
- **Provenance you can check.** Faye only ever receives preview URLs that Swordfish itself provisioned from the
  SHA-pinned QA worktree, and the SHA, ports, and service PIDs are recorded in the QA evidence manifest.
- **A QA failure restarts the whole pipeline**, because the fix is a new commit and a new commit invalidates
  everything.

## Where it stands

**Designed.** Faye's seat, the browser stack, QA environment preparation, and the evidence manifest do not exist.
What counts as proof that QA ran against the candidate rather than against something else is an open question,
and cryptographic attestation of what a preview served is explicitly deferred.

## Acceptance criteria

Owns [`ABSTRACT.md`](../../ABSTRACT.md) §8 criteria **25** (after CI and review pass, faye starts QA in a clean
environment), **26** (faye can access a private preview and browser tooling), and **27** (faye saves structured
results and visual or recorded evidence).

## Decisions

- [Verification runs in a clean-room worktree (ADR 0015)](../adr/0015-verification-runs-in-a-clean-room-worktree.md)
- [Every commit invalidates every downstream result (ADR 0016)](../adr/0016-every-commit-invalidates-every-downstream-result.md)
- [The VM is the sandbox (ADR 0012)](../adr/0012-the-vm-is-the-sandbox.md) — faye's locked profile, and why
  vendor diversity lands at the least judgment-critical seat.
- [Continue preserves an attempt; rerun replaces it (ADR 0041)](../adr/0041-continue-preserves-an-attempt-rerun-replaces-it.md)
- [Cowboys approve or reject, and a rejection carries notes (ADR 0050)](../adr/0050-cowboys-approve-or-reject-and-a-rejection-carries-notes.md)
  — why faye's verdict is derived from its scenarios while jet's is declared.

Previews are always private; public preview sharing is out of scope for this effort.
