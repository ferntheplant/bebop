# Specs

One spec is one PR's worth of work — the shape `/to-spec` produces: problem statement, solution, user stories,
implementation decisions, testing decisions, out of scope.

A spec is written at `.scratch/<feature-slug>/spec.md` while it is in flight and archived here as
`NNNN-<slug>.md` once it ships. Archived specs are history, not authority: they record what one change set was
meant to do at the time. Anything in a spec still worth defending months later should have graduated to an
[ADR](../adr/) by then.

Do not confuse this with a bounty's **effective spec**, which is the structured statement of what one bounty is
supposed to accomplish inside the product — see [`CONTEXT.md`](../../CONTEXT.md).
